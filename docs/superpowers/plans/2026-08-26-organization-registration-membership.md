# Organization Registration and Membership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add password-based organization registration, join approval, and strict organization-scoped authorization while preserving existing local accounts and the LexFlow dashboard.

**Architecture:** Introduce a versioned tenant migration that places the existing workspace in a default organization, then isolate registration logic in focused domain modules. Public registration routes create only organizations, join requests, and invite-backed accounts; every existing authenticated query is scoped from `request.user.organization_id`. Registration uses the existing session cookie and dashboard shell, with a new responsive wizard that reuses current design tokens.

**Tech Stack:** Node.js 22+, Express 5, built-in `node:sqlite`, built-in crypto, vanilla HTML/CSS/JavaScript, Node test runner.

## Global Constraints

- Preserve all existing user IDs, password hashes, sessions, rules, departments, settings, emails, owners, notifications, activity, connectors, and local test credentials during migration.
- `User` is UI copy for the stored `member` role.
- Passwords created through registration require at least 10 characters; existing password hashes and login behavior remain valid.
- Unverified domains are descriptive and are not globally unique.
- Organization handles and join codes are globally unique, opaque enough for discovery, and generated by the server.
- A registered email is globally unique and a user belongs to exactly one organization.
- Logo types are PNG, JPEG, or WebP; maximum size is 2 MiB; width and height must each be 64–2,048 pixels.
- Join requests are limited to five attempts per normalized email and source address per rolling hour.
- Registration invites are hashed, single-use, and expire after 24 hours.
- Cross-organization records return a resource-hiding `404` where a resource identifier is involved.
- Preserve the warm-gray, floating-white, coral bento design and all current accessibility behavior.

- [ ] **Step 3: Implement the idempotent tenant migration**

Before any organization schema write on a file database, create a timestamped SQLite online backup, open it independently, require `PRAGMA integrity_check = 'ok'`, and compare the core table row counts. In-memory tests skip backup. Only then create tables for `organizations`, `organization_assets`, `join_requests`, `registration_invites`, and `join_request_attempts`. Add/backfill `organization_id` on current tables, add `registration_status` and `mailbox_provider` on users, rebuild `departments`, `workspace_settings`, `sync_state`, and `email_thread_owners` with composite tenant keys, and create organization-aware indexes. Add database triggers that abort cross-organization user references with `organization mismatch`.

```js
export const DEFAULT_ORGANIZATION_HANDLE = 'lexflow-local';

export function migrateOrganizations(db, { now = new Date() } = {}) {
  db.exec('SAVEPOINT organization_migration');
  try {
    createOrganizationTables(db);
    const organizationId = ensureDefaultOrganization(db, now.toISOString());
    addAndBackfillOrganizationColumns(db, organizationId);
    rebuildTenantKeyedTables(db, organizationId);
    createTenantIndexesAndTriggers(db);
    db.exec('PRAGMA user_version = 2');
    db.exec('RELEASE organization_migration');
  } catch (error) {
    db.exec('ROLLBACK TO organization_migration');
    db.exec('RELEASE organization_migration');
    throw error;
  }
}

export function createDatabase(filename = ':memory:', { now = new Date() } = {}) {
  const db = openDatabase(filename);
  if (filename !== ':memory:' && organizationMigrationRequired(db)) {
    createVerifiedMigrationBackup(db, filename, now);
  }
  migrate(db);
  return db;
}
```

```js
export function normalizeEmail(value) {
  const email = String(value ?? '').trim().toLocaleLowerCase('en-US');
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) throw invalid('email', 'Enter a valid email address.');
  return email;
}

export function providerForEmail(email, requestedProvider) {
  const domain = normalizeEmail(email).split('@')[1];
  if (domain === 'gmail.com') return 'gmail';
  if (['outlook.com', 'hotmail.com', 'live.com'].includes(domain)) return 'outlook';
  if (!['gmail', 'outlook'].includes(requestedProvider)) {
    throw invalid('mailboxProvider', 'Choose Gmail or Outlook for this address.');
  }
  return requestedProvider;
}
```
